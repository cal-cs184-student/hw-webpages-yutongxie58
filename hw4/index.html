Overview

In this assignment, we implemented a cloth simulation using a mass-spring system. The cloth is modeled as a grid of point masses connected by structural, shearing, and bending springs. We simulated cloth motion using Verlet integration, handled collisions with objects and with itself, and applied different shaders for rendering. These components together produce realistic cloth behavior.

Part 1: Masses and springs

We implemented Cloth::buildGrid() by creating point masses in row-major order and adding structural, shearing, and bending springs between neighboring masses. Pinned masses are set according to the scene file.

Part 2: Simulation via numerical integration

Experimentation with parameters

We tested how ks, density, and damping affect cloth behavior using scene/pinned2.json. Increasing ks from 500 to 50000 makes the cloth much stiffer and reduces stretching. Lower ks makes the cloth more flexible and causes larger deformations. Increasing density from 1 to 50 increases the mass of each point, causing the cloth to sag more under gravity. Lower density makes the cloth lighter and results in less sagging. Increasing damping from 0.01 to 0.55 reduces oscillations and allows the cloth to settle more quickly. Lower damping causes the cloth to swing more before stabilizing.

Part 3: Handling collisions with other objects

Implementation

We implemented collision handling for both spheres and planes. For sphere collision, if a point mass moves inside the sphere, we compute the tangent point on the sphere surface along the direction from the sphere center to the point mass. We then move the point mass to this tangent point, scaled by (1 - friction), to simulate energy loss during collision. For plane collision, we check whether the point mass crosses the plane between the previous and current timestep. If it does, we compute the intersection point with the plane and move the point mass slightly above the surface using SURFACE_OFFSET, scaled by (1 - friction).

Part 4: Handling self-collisions

Implementation

We implemented self-collision using spatial hashing to keep the cost manageable. Three pieces. hash_position partitions space into 3D boxes of size (3 * width / num_width_points, 3 * height / num_height_points, max(w, h)), snaps a position to its box with fmod, and combines the box coordinates into a single float using prime multipliers (31, 97, 53). build_spatial_map walks every point mass and appends a pointer to it into the bucket for its hashed key, allocating a new vector<PointMass *> lazily when a key is first seen. self_collide looks up the bucket for the point mass's own position, iterates the candidates, skips itself, and for each candidate within 2 * thickness distance accumulates a correction vector that pushes the pair apart. The mean correction is divided by simulation_steps and added to the point mass position. Finally we hooked this into simulate: each timestep we call build_spatial_map once and then self_collide on every point mass between the Verlet integration and the collision-object pass.

Falling and folding sequence

With self-collision off the cloth would clip through itself and end up as a flat sheet. With our spatial-hash repulsion the layers stack correctly. The rest state still has minor residual motion since our Verlet model has no damped spring force, which the spec explicitly says is fine.

Density variation

Lighter cloth (density = 1) drifts down slowly and the fabric retains its shape mid-fall — gravity force is small relative to the spring forces holding the cloth together. Heavier cloth (density = 500) drops fast and creates pronounced compressed folds on impact because each point mass carries more momentum into the collision.

ks variation

Weak springs (ks = 500) let the cloth stretch and crumple into thicker bundles when it lands. Stiff springs (ks = 50000) keep the cloth nearly flat as it falls and the resting shape has shorter, sharper wave patterns instead of soft compressed bunching.

Part 5: Shaders

What a shader program is

A shader program is a small program that runs on the GPU as part of the rendering pipeline. We use two stages here. The vertex shader runs once per vertex and is responsible for transforming positions into screen space and writing out per-vertex values (world position, normal, UV, tangent) that the rasterizer interpolates across the triangle. The fragment shader then runs once per pixel-sized fragment, taking those interpolated values as input and computing the final color. Lighting and material effects come from doing math in the fragment shader on the interpolated normal and position relative to the camera and light positions, then optionally sampling from textures or cubemaps.

Blinn-Phong

Blinn-Phong combines three components into a single shading model. Ambient is a constant color added to every fragment, modeling weak bounced light filling shadows. Diffuse is Lambertian k_d * (I / r^2) * max(0, n . l), dimmer where the surface faces away from the light. Specular is k_s * (I / r^2) * max(0, n . h)^p using the halfway vector h = normalize(l + v), producing a tight highlight that depends on the camera angle. We used k_a = 0.3, k_d = 1.0, k_s = 0.5, p = 32, and I_a = 1.0.

Bump and Displacement mapping

Bump mapping fakes surface detail by perturbing the normal in the fragment shader using the gradient of a height map. dU = (h(u + 1/w, v) - h(u, v)) * k_h * k_n and similarly for dV in the vertical direction. The local-space normal (-dU, -dV, 1) is rotated into world space by the TBN matrix and then plugged into the same Blinn-Phong calculation we wrote earlier. The geometry doesn't actually change — only the normals do. Displacement mapping does the same shading, but in addition the vertex shader pushes each vertex along its normal by h(u, v) * k_h. Real geometry moves, so the silhouette changes too. We used the brick texture (texture_4) for both.

Sphere coarseness comparison

We rendered each shader at -o 16 -a 16 (very coarse sphere mesh) and -o 128 -a 128 (fine mesh). For bump mapping, the underlying sphere geometry is unchanged either way, so the only effect of changing coarseness is on the cloth-sphere contact surface and on the silhouette where the cloth wraps over the sphere top. For displacement mapping, the actual vertices are being pushed by the height map, so the coarse mesh produces a chunkier, more pronounced relief because each displaced triangle covers a larger area, while the fine mesh gives a smoother, more continuous surface relief.

Mirror (environment-mapped reflection)

For the mirror shader we compute the outgoing eye-ray wo = normalize(u_cam_pos - v_position), reflect it across the surface normal with wi = reflect(-wo, n), and sample the environment cubemap in direction wi. No shadow rays — the assumption is that the sky is infinitely far and there's nothing in between.
