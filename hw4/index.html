Overview

In this assignment, we implemented a cloth simulation using a mass-spring system. The cloth is modeled as a grid of point masses connected by structural, shearing, and bending springs. We simulated cloth motion using Verlet integration, handled collisions with objects and with itself, and applied different shaders for rendering. These components together produce realistic cloth behavior.

Part 1: Masses and springs

We implemented Cloth::buildGrid() by creating point masses in row-major order and adding structural, shearing, and bending springs between neighboring masses. Pinned masses are set according to the scene file.

Experimentation with parameters

We tested how ks, density, and damping affect cloth behavior using scene/pinned2.json. Increasing ks from 500 to 50000 makes the cloth much stiffer and reduces stretching. Lower ks makes the cloth more flexible and causes larger deformations. Increasing density from 1 to 50 increases the mass of each point, causing the cloth to sag more under gravity. Part 3: Handling collisions with other objects

Implementation

We implemented collision handling for both spheres and planes. For sphere collision, if a point mass moves inside the sphere, we compute the tangent point on the sphere surface along the direction from the sphere center to the point mass. We then move the point mass to this tangent point, scaled by (1 - friction), to simulate energy loss during collision. For plane collision, we check whether the point mass crosses the plane between the previous and current timestep. If it does, we compute the intersection point with the plane and move the point mass slightly above the surface using SURFACE_OFFSET, scaled by (1 - friction).

Part 4: Handling self-collisions

Implementation

We implemented self-collision using spatial hashing. hash_position partitions space into 3D boxes of size (3 * width / num_width_points, 3 * height / num_height_points, max(w, h)) and combines the box coordinates into a single float using prime multipliers. build_spatial_map clears the hash table and inserts every point mass into its corresponding bucket. self_collide looks up nearby candidates from the bucket, skips itself, and pushes the point mass away from any candidate within 2 * thickness distance. The total correction is averaged and divided by simulation_steps. We call build_spatial_map and self_collide in simulate right after Verlet integration.

Cloth falling and folding on itself

We can see the cloth start folding on itself as it falls and lands in stacked layers without clipping through itself.

Density variation

Lower density makes the cloth lighter and slower to fall, with smaller and softer folds. Higher density makes the cloth heavier and creates larger, more compressed folds when it lands.

ks variation

Lower ks makes the springs weaker, so the cloth stretches more and bunches up in thicker layers. Higher ks keeps the cloth stiff and produces shallower, more rigid folds.

Part 5: Shaders

Shader programs

A shader program is a small program that runs on the GPU during rendering. The vertex shader runs once per vertex and outputs the vertex position in screen space along with values like world position, normal, and UV coordinates. The fragment shader runs once per fragment and uses the interpolated values from the vertex shader to compute the final pixel color. Together they let us implement different lighting and material effects by changing how positions and colors are computed on the GPU.

Blinn-Phong shading

The Blinn-Phong model combines three components: ambient, diffuse, and specular. Ambient is a constant base color added to every fragment. Diffuse depends on how much the surface normal faces the light. Specular depends on the halfway vector between the light direction and the view direction, raised to a shininess exponent. We used k_a = 0.3, k_d = 1.0, k_s = 0.5, p = 32.

Texture mapping

We replaced texture_1.png with a custom image and rendered with the Texture shader, which samples the texture using the interpolated UV coordinates of each fragment.

Bump and Displacement mapping

Bump mapping perturbs the surface normal using the gradient of a height map but leaves the geometry unchanged. Displacement mapping does the same shading, but the vertex shader also pushes each vertex along its normal by the height map value, so the actual geometry changes. We used texture_4.png for both. The displacement render shows more pronounced surface detail because the geometry actually moves, while bump only fakes it through shading.

Sphere coarseness comparison

We rendered both shaders at -o 16 -a 16 and -o 128 -a 128. With the coarse sphere, displacement creates chunkier surface detail since each large triangle gets pushed by the same height value. The fine sphere gives smoother and more detailed displacement. Bump mapping looks similar across both because the geometry never changes, only the shading.

Mirror

The mirror shader computes the eye ray from the camera to the fragment, reflects it across the surface normal, and samples the environment cubemap in that direction. The cloth and sphere look like polished metal reflecting the surrounding sky.
